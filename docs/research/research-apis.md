# macOS Notch-Hub App API Research (current through macOS 26 Tahoe, mid-2026)

Primary reference implementations studied at source level: TheBoredTeam/boring.notch (MIT-adjacent GPL, actively maintained, ships mediaremote-adapter + CGSSpace + XPC helper), AlexPerathoner/SlimHUD, AryanRogye/ComfyNotch, ungive/mediaremote-adapter. All code cited below was read from the current main branches (July 2026).

## 1. Notch geometry (NSScreen)
- `NSScreen.safeAreaInsets` (macOS 12+) returns `NSEdgeInsets`; `.top > 0` iff the screen has a notch (38 pt on 16" MBP, 32 pt on 14"). Detection: `NSScreen.screens.contains { $0.safeAreaInsets.top > 0 }` (this is literally boring.notch's `deviceHasNotch()`).
- `NSScreen.auxiliaryTopLeftArea` / `auxiliaryTopRightArea` are `NSRect?` in global screen coordinates describing the usable menu-bar strips either side of the notch; `nil` on non-notched displays.
- Exact math: `notchWidth = screen.frame.width - auxiliaryTopLeftArea!.width - auxiliaryTopRightArea!.width`; `notchHeight = screen.safeAreaInsets.top`. Notch rect (bottom-left origin, global coords): `CGRect(x: auxiliaryTopLeftArea!.maxX, y: screen.frame.maxY - safeAreaInsets.top, width: notchWidth, height: safeAreaInsets.top)`. The notch is always horizontally centered: `midX = screen.frame.midX`.
- Fallback for external/non-notch displays: draw a "virtual notch" of fixed size; menu bar height = `screen.frame.maxY - screen.visibleFrame.maxY` (or `NSStatusBar.system.thickness`). Caveat: in a fullscreen space with menu bar hidden, visibleFrame changes; safeAreaInsets does not.
- Multi-display keying: derive a stable UUID per screen via `screen.deviceDescription[NSDeviceDescriptionKey("NSScreenNumber")] as! CGDirectDisplayID` → `CGDisplayCreateUUIDFromDisplayID`. boring.notch keys its window/viewmodel dictionaries on this and rebuilds on `NSApplication.didChangeScreenParametersNotification` (comparing screen UUID sets + frames).
- Info.plist `NSPrefersDisplaySafeAreaCompatibilityMode = false` avoids the scaled "compatibility mode" that hides the notch from the app.

## 2. Always-on-top borderless panel over the notch
boring.notch's exact window config (BoringNotchWindow: NSPanel):
- styleMask: `[.borderless, .nonactivatingPanel, .utilityWindow, .hudWindow]`
- `isFloatingPanel = true; isOpaque = false; backgroundColor = .clear; hasShadow = false; isMovable = false; titleVisibility = .hidden; titlebarAppearsTransparent = true; isReleasedWhenClosed = false`
- `level = .mainMenu + 3` (NSWindow.Level(rawValue: NSWindow.Level.mainMenu.rawValue + 3); mainMenu raw = 24). Alternatives: `.statusBar` (25), `.screenSaver` (1000), `CGShieldingWindowLevel()` for above-everything. Above-mainMenu levels keep the panel visible over the menu bar area / notch.
- `collectionBehavior = [.fullScreenAuxiliary, .stationary, .canJoinAllSpaces, .ignoresCycle]` — fullScreenAuxiliary lets the panel appear over fullscreen spaces; canJoinAllSpaces keeps it on every Space; stationary excludes it from Exposé; ignoresCycle keeps it out of Cmd-backtick.
- Override `canBecomeKey`/`canBecomeMain` → false (nonactivating; hover/click never steals focus from the frontmost app). Content = `NSHostingView(rootView: ContentView().environmentObject(vm))`, then `orderFrontRegardless()`.
- Positioning: `window.setFrameOrigin(NSPoint(x: screenFrame.origin.x + screenFrame.width/2 - window.frame.width/2, y: screenFrame.origin.y + screenFrame.height - window.frame.height))`.
- **Surviving fullscreen / menu-bar auto-hide (the NotchNook/boring.notch trick)**: the AppKit-only setup can still be occluded in some fullscreen cases, so boring.notch additionally attaches the window to a private SkyLight/CoreGraphics "space" that renders above everything: `CGSSpaceCreate(_CGSDefaultConnection(), 0x1, nil)` (flag MUST be 1 or Finder redraws desktop icons), `CGSSpaceSetAbsoluteLevel(cid, space, 2147483647)`, `CGSShowSpaces`, then `CGSAddWindowsToSpaces(cid, [window.windowNumber], [spaceID])`. Declared via `@_silgen_name("_CGSDefaultConnection")` etc. (full wrapper in boringNotch/private/CGSSpace.swift, originally from avaidyam/Parrot). The space must be destroyed (`CGSHideSpaces` + `CGSSpaceDestroy`) on exit. They gate this "SkyLightWindow" mode to the lock screen (DistributedNotificationCenter `com.apple.screenIsLocked`/`com.apple.screenIsUnlocked`) and use the plain NSPanel path otherwise — plain fullScreenAuxiliary + level > mainMenu is sufficient over fullscreen apps because the panel's window level exceeds the (hidden) menu bar's and fullScreenAuxiliary admits it into the fullscreen space.
- Mouse handling: panel stays `ignoresMouseEvents = false` so hover-to-open works; hover detection via SwiftUI `.onHover` on the notch shape. For detecting file drags while closed, boring.notch runs a `DragDetector` (global `NSEvent.addGlobalMonitorForEvents(matching: .leftMouseDragged)` + drag pasteboard inspection) against the computed notch region and auto-opens the shelf.
- App is an accessory app (`MenuBarExtra` scene + `applicationShouldTerminateAfterLastWindowClosed → false`; LSUIElement/`.accessory` activation policy).

## 3. System HUD suppression + volume/brightness/media keys
**OSDUIHelper suppression (SlimHUD's OSDUIManager, verbatim technique, no SIP disable needed):**
- stop(): run `/bin/launchctl kickstart gui/\(getuid())/com.apple.OSDUIHelper` and waitUntilExit (kickstart because OSDUIHelper isn't running until the first volume key after boot), `usleep(500000)` to let it start, then `/usr/bin/killall -STOP OSDUIHelper` (SIGSTOP freezes the agent so the bezel HUD never draws).
- start()/restore: `/usr/bin/killall -9 OSDUIHelper` (launchd respawns it on demand). ComfyNotch hardens this with a repeating 3-second Timer that re-runs the kickstart+STOP sequence (macOS occasionally restarts the agent), and on teardown posts a synthetic volume key or `osascript -e "set volume output volume (output volume of (get volume settings))"` to force the HUD process to refresh.
**Volume monitoring (CoreAudio), boring.notch VolumeManager:** get default output device (`kAudioHardwarePropertyDefaultOutputDevice` on `kAudioObjectSystemObject`), then `AudioObjectAddPropertyListenerBlock` on: (a) the system object for default-device changes (re-subscribe), (b) `kAudioDevicePropertyVolumeScalar` scope `kAudioDevicePropertyScopeOutput` element `kAudioObjectPropertyElementMain` — falling back to per-channel elements 1/2 when the master element is absent, (c) `kAudioDevicePropertyMute`. Read volume with `AudioObjectGetPropertyData` (validate size == MemoryLayout<Float32>.size), averaging elements [main,1,2,3,4]; write via `AudioObjectSetPropertyData`; software-mute fallback (store previous volume, set 0) when the device lacks the mute property. The simpler `kAudioHardwareServiceDeviceProperty_VirtualMainVolume` (renamed from VirtualMasterVolume) with the same AudioObjectPropertyAddress pattern also works and abstracts hardware/virtual volume. AppleScript last-resort read: `output volume of (get volume settings)`.
**Brightness:** no public API. dlopen `/System/Library/PrivateFrameworks/DisplayServices.framework/DisplayServices`, dlsym `DisplayServicesGetBrightness` / `DisplayServicesSetBrightness`, typed `@convention(c) (CGDirectDisplayID, UnsafeMutablePointer<Float>) -> Int32` and `(CGDirectDisplayID, Float) -> Int32` (or `@_silgen_name` declarations as in Sapphire/MonitorControl). Runs as user — no root, no TCC prompt. Poll after brightness keys or on a timer; there is no change-notification API. boring.notch moved DisplayServices + keyboard-backlight calls into an XPC helper (BoringNotchXPCHelper) to isolate private-API use; keyboard backlight uses the private KeyboardBrightnessClient/IOKit HID path.
**Media/system keys via CGEventTap (boring.notch MediaKeyInterceptor, complete recipe):** `CGEvent.tapCreate(tap: .cghidEventTap, place: .headInsertEventTap, options: .defaultTap, eventsOfInterest: CGEventMask(1 << 14))` — 14 is the NSSystemDefined CGEventType. In the callback, build `NSEvent(cgEvent:)`, require `type == .systemDefined && subtype.rawValue == 8`, decode `keyCode = (data1 & 0xFFFF_0000) >> 16` and `state = (data1 & 0xFF00) >> 8` (0xA keyDown, 0xB keyUp). Key codes: NX_KEYTYPE_SOUND_UP=0, SOUND_DOWN=1, BRIGHTNESS_UP=2, BRIGHTNESS_DOWN=3, MUTE=7, PLAY=16, keyboardIllumUp/Down=21/22. Return `nil` from the callback to swallow the key (so the system HUD/action never fires and you do the adjustment yourself), or `Unmanaged.passRetained(cgEvent)` to pass through. Add via `CFMachPortCreateRunLoopSource` + `CFRunLoopAddSource(CFRunLoopGetMain(), src, .commonModes)`, `CGEvent.tapEnable`. Requires Accessibility permission (`AXIsProcessTrustedWithOptions([kAXTrustedCheckOptionPrompt: true])`); boring.notch routes the AX check/prompt through its XPC helper. Handle `.tapDisabledByTimeout` by re-enabling the tap. Synthesize a media key: `NSEvent.otherEvent(with: .systemDefined, ..., subtype: 8, data1: (keyCode << 16) | (0xA << 8), data2: -1)?.cgEvent?.post(tap: .cghidEventTap)`.

## 4. EventKit (macOS 14+)
`EKEventStore.authorizationStatus(for: .event)` now returns `.fullAccess` / `.writeOnly` (`.authorized` is deprecated). Request with `try await store.requestFullAccessToEvents()` (and `requestFullAccessToReminders()`); Info.plist keys `NSCalendarsFullAccessUsageDescription` / `NSRemindersFullAccessUsageDescription`; sandbox entitlement `com.apple.security.personal-information.calendars`. Query via `predicateForEvents(withStart:end:calendars:)` + `events(matching:)`; live-refresh on `.EKEventStoreChanged` NotificationCenter observer (boring.notch CalendarManager does exactly this and re-filters calendars by `calendarIdentifier` sets persisted in Defaults). Reminders: `predicateForReminders(in:)`, complete via `reminder.isCompleted = true; try store.save(reminder, commit: true)`.

## 5. Camera mirror (AVCaptureSession)
`AVCaptureDevice.requestAccess(for: .video)` + `NSCameraUsageDescription`. Enumerate with `AVCaptureDevice.DiscoverySession(deviceTypes: [.external, .builtInWideAngleCamera], mediaType: .video, position: .unspecified)` (`.external` is the macOS 14+ replacement for `.externalUnknown`; add `.continuityCamera` if desired). Configure on a dedicated serial queue: `session.beginConfiguration(); session.sessionPreset = .high; session.addInput(try AVCaptureDeviceInput(device: device)); session.commitConfiguration()`. Preview: `AVCaptureVideoPreviewLayer(session:)`, `videoGravity = .resizeAspectFill`, hosted in a layer-backed NSView via NSViewRepresentable. Mirroring: `previewLayer.connection?.automaticallyAdjustsVideoMirroring = false; previewLayer.connection?.isVideoMirrored = true` (or cheap SwiftUI `scaleEffect(x: -1, y: 1)`). Watch `.AVCaptureDeviceWasConnected/Disconnected` to rebuild; `startRunning()` off the main thread.

## 6. AirDrop
`NSSharingService(named: .sendViaAirDrop)` → `guard service.canPerform(withItems: urls)` → `service.perform(withItems: urls)` on the main thread; items are file URLs (or NSImage/strings). For a picker UI: `NSSharingServicePicker(items:).show(relativeTo: .zero, of: nsView, preferredEdge: .minY)`. boring.notch discovers all share providers at runtime (ShareServiceFinder wrapping the deprecated `NSSharingService.sharingServices(forItems:)`), caches `NSSharingService` objects by title, sorts "AirDrop" first, and sets a lifecycle delegate (`NSSharingServiceDelegate`) to keep the notch panel open while the share sheet runs. Sandboxed apps must wrap shared file URLs in `startAccessingSecurityScopedResource()` for the duration of the share.

## 7. Drag-and-drop file shelf
**Drop in (SwiftUI):** `.onDrop(of: [.fileURL, .url, .utf8PlainText, .plainText, .data], isTargeted: $binding) { providers in ... }`; resolve providers with `loadItem(forTypeIdentifier: UTType.fileURL.identifier)` → `URL(dataRepresentation:relativeTo:)`. Persist shelf items as security-scoped bookmarks (`url.bookmarkData(options: .withSecurityScope)`), re-resolve + `startAccessingSecurityScopedResource()` before any use.
**Drag out (robust AppKit path, boring.notch ShelfItemView):** SwiftUI `.onDrag`/Transferable is unreliable from a nonactivating panel, so they embed an `NSViewRepresentable` whose NSView implements `mouseDragged` with a 3 pt threshold, builds `NSPasteboardItem`s (`setString(url.absoluteString, forType: .fileURL)` + `.string` path; `.URL` for links), wraps each in `NSDraggingItem(pasteboardWriter:)` with `setDraggingFrame(_:contents:)` using an `ImageRenderer`-prerendered preview NSImage, and calls `beginDraggingSession(with:event:source:)`. The view conforms to `NSDraggingSource`: `sourceOperationMaskFor context` returns `[.copy, .move]` for `.outsideApplication`; `draggingSession(_:endedAt:operation:)` stops security-scoped access and optionally auto-removes shelf items on successful drop. Security-scoped access is started per-URL at drag begin. For files that don't exist yet, use `NSFilePromiseProvider(fileType: UTType.identifier, delegate:)` with `filePromiseProvider(_:writePromiseTo:completionHandler:)`. SwiftUI-only alternative for simple cases: `.draggable(item)` with `Transferable`/`FileRepresentation(exportedContentType:)`.
**Auto-open shelf on drag-hover:** global event monitor (DragDetector) watching `.leftMouseDragged` against the notch region rect, opening the panel to shelf view when a drag enters.

## 8. Launch at login
`import ServiceManagement`; `try SMAppService.mainApp.register()` / `try SMAppService.mainApp.unregister()`; read `SMAppService.mainApp.status == .enabled` fresh each time (never cache — user can toggle in System Settings > General > Login Items); statuses: `.enabled/.notRegistered/.requiresApproval/.notFound`; deep-link users with `SMAppService.openSystemSettingsLoginItems()`. macOS 13+, fine on 26.

## 9. Now playing (the hard one)
- **State of restriction:** since macOS 15.4, `mediaremoted` enforces an entitlement check; in-process `MRMediaRemoteGetNowPlayingInfo` returns nothing for normal apps. Processes whose bundle ID starts with `com.apple.` are still allowed — `/usr/bin/perl` reports as `com.apple.perl5`, which is the loophole. Still broken/no public API in macOS 26 (Apple feedback FB17228659 open); the workaround is confirmed working on macOS 26.0 (mediaremote-adapter README badge, last tested against 26 beta/release).
- **mediaremote-adapter (ungive/mediaremote-adapter, BSD-3):** bundle `mediaremote-adapter.pl` (Resources) + `MediaRemoteAdapter.framework` (Contents/Frameworks, bundled but NOT linked; built via CMake, x86_64+arm64). Spawn: `Process()` with `executableURL = /usr/bin/perl`, `arguments = [scriptURL.path, Bundle.main.privateFrameworksPath! + "/MediaRemoteAdapter.framework", "stream"]`, stdout → `Pipe`. Output is JSON-lines: `{"type":"data","diff":Bool,"payload":{...}}` with keys `bundleIdentifier, parentApplicationBundleIdentifier, playing, title, artist, album, duration, elapsedTime, timestamp (ISO8601), playbackRate, artworkData (base64), artworkMimeType, shuffleMode, repeatMode, ...`. Diffing on by default (merge into last full payload; null = key removed); flags `--no-diff`, `--debounce=N`, `--no-artwork`, `--micros`. Other commands: `get`, `send N` (0 play, 1 pause, 2 toggle, 4 next, 5 prev, 8-11 seek start/stop, 12/13 ±15 s), `seek MICROS`, `shuffle 1|2|3`, `repeat 1|2|3`, `speed N`, and `test` (bundle MediaRemoteAdapterTestClient; exit 0 = adapter functional — use it to auto-fall back to AppleScript when a future macOS breaks this). boring.notch's NowPlayingController is a complete Swift consumer: actor-based JSON-lines pipe reader, Codable payload structs, SIGTERM/terminate on deinit. Maintained Swift package fork: ejbills/mediaremote-adapter.
- **Sending commands in-process still works**: boring.notch still dlopens `/System/Library/PrivateFrameworks/MediaRemote.framework` via `CFBundleCreate` + `CFBundleGetFunctionPointerForName` for `MRMediaRemoteSendCommand`, `MRMediaRemoteSetElapsedTime`, `MRMediaRemoteSetShuffleMode`, `MRMediaRemoteSetRepeatMode` (`unsafeBitCast` to `@convention(c)`) — the 15.4 lockdown hit reading, not command sending. Use the adapter's `send` as the conservative path.
- **MPNowPlayingSession / MediaPlayer.framework**: not a solution — on macOS these APIs publish YOUR app's now-playing state (MPNowPlayingInfoCenter, MPRemoteCommandCenter); there is no public read API for other apps' playback.
- **One-shot no-dependency fallback**: `osascript`/JXA calling `MRNowPlayingRequest` (SKaplan gist) still returns title/artist on 15.4–26, but no artwork and no realtime stream.
- **App-specific fallback (AppleScript/ScriptingBridge)**: `tell application "Spotify"/"Music"` for playpause/next/previous, `player position`, `sound volume`, track metadata, Music favoriting (`set favorited of current track`). Requires `NSAppleEventsUsageDescription` + `com.apple.security.automation.apple-events` and per-target-app TCC consent. Free realtime triggers without TCC: DistributedNotificationCenter `com.spotify.client.PlaybackStateChanged` and `com.apple.Music.playerInfo` notifications.

## Architectural note
boring.notch isolates all private-API/TCC-sensitive work (Accessibility check+prompt, DisplayServices brightness, keyboard backlight) in a bundled XPC helper (BoringNotchXPCHelper) so the main app remains cleaner; consider the same split. The whole app is unsandboxed (required for launchctl/killall Process calls, CGEventTap, dlopen of private frameworks) — a notch hub of this type cannot ship in the Mac App Store.
