# Notchi — confirmed identity

Notchi is real and open source (GPL-3.0): **github.com/sk-ruban/notchi**, site notchi.app (site 403s to bots; GitHub Pages serves it, Sparkle appcast at updates.notchi.app/appcast.xml). ~96% Swift (SwiftUI + AppKit), macOS 15.0+, MacBook-with-notch required, v1.2.0 current. It is a pixel-art "Tamagotchi in the notch" for **Claude Code and OpenAI Codex CLI/desktop** sessions. I cloned and read the full source; everything below is from code, not marketing copy.

# What it displays

**Collapsed notch**: a grass-island strip flanking the physical notch with one animated pixel sprite per live session (Claude sprite family vs Codex sprite family, provider accent colors). Sprite animation state = session state: `idle, working, sleeping, compacting, waiting, waving` × emotion `neutral, happy, elated, sad, sob` (sprite sheets named e.g. `claude_working_happy`). Working shows a shimmering spinner verb; a usage ring appears at the notch edge. Sleep state after 300s inactivity.

**Expanded panel (450×450, click notch to open)**: session list rows with colored state dot / processing spinner, title `"<projectName> #<N> - <lastUserPrompt|codexTitle>"` where projectName = last path component of session `cwd`; live activity feed (tool events with derived descriptions + statuses running/success/error, assistant messages rendered as markdown, keeps last 20 events / 10 messages); permission-mode badge (Plan Mode / Accept Edits / Don't Ask / Bypass); usage bar with % (green <50, amber <80, red ≥80), "Resets in Xh Ym", Extra Usage indicator; usage detail page with Claude/Codex toggle, 5-hour + weekly + model-scoped-weekly quota bars, Codex session/weekly/code-review windows + credits balance; cost dashboard with 30-day daily spend bar chart (hover = day cost + tokens) per model.

It does NOT show live per-turn token streams in the notch; tokens appear as cost history (parsed from transcripts) and Codex context/compaction signals.

# Detection architecture (the core answer)

`Claude Code / Codex → shell-script hooks → Unix socket /tmp/notchi.sock → JSON envelope parser → per-session state machine → sprites`.

**Claude side**: on launch the app writes `notchi-hook.sh` to `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/hooks/` and idempotently upserts `~/.claude/settings.json` hooks for: UserPromptSubmit, SessionStart, PreToolUse (matcher `*`), PostToolUse (`*`), PermissionRequest (`*`), PreCompact (matchers `auto`+`manual`), Stop, SubagentStop, SessionEnd — all pointing at the one script (`{"type":"command","command":"..."}`). Uninstall prunes only notchi-owned entries. The hook script (bash + inline python3) reads the hook JSON from stdin, maps event→status (UserPromptSubmit→processing, PreToolUse→running_tool, PostToolUse→processing, PreCompact→compacting, SessionStart/PermissionRequest/Stop/SubagentStop→waiting_for_input, SessionEnd→ended), detects non-interactive `claude -p/--print` runs by walking parent PIDs' argv, finds the actual `claude` process PID by walking `ps -axo pid,ppid,command` ancestry (≤8 hops), and sends one JSON blob to the socket: `{provider, session_id, transcript_path, cwd, event, status, interactive, permission_mode, user_prompt, tool, tool_use_id, tool_input, permission_suggestions, claude_process_id}`. If the socket doesn't exist (app closed) it exits silently — zero overhead.

**Codex side**: writes `notchi-codex-hook.sh` to `~/.codex/hooks/`, upserts `~/.codex/hooks.json` (SessionStart matcher `startup|resume`, UserPromptSubmit, Stop with timeout 30) and forces `[features]\ncodex_hooks = true` in `~/.codex/config.toml`. Codex only emits 3 hook events, so Notchi fills the gaps from the rollout transcript (see below). Hook also reports `codex_process_id` and `codex_origin` (`cli` if the process has a tty, `desktop` if tty is `??`), and detects image attachments by re-reading the last 200 transcript lines for the matching `user_message` payload.

**Socket server**: AF_UNIX SOCK_STREAM at `/tmp/notchi.sock`, chmod 0600, non-blocking accept via DispatchSourceRead, per-client 0.5s poll read timeout, stale-socket probe (connect → ECONNREFUSED = stale, unlink and rebind, with 8×250ms retries).

**Transcript tailing (the second detection channel)**: on UserPromptSubmit it records the current transcript byte offset, then attaches a `DispatchSource.makeFileSystemObjectSource(fd, [.write, .extend])` watcher to the transcript file, and on every write does a debounced (100ms) incremental parse from the saved offset (`FileHandle.seek`), resetting if the file shrank. Claude transcript path comes from the hook, with fallback derivation `~/.claude/projects/<cwd with "/" and "." → "-">/<session_id>.jsonl`. Claude parsing: assistant lines (`"type":"assistant"`, skip `isMeta` and `model == "<synthetic>"`) become feed messages; a user line containing `"text":"[Request interrupted by user` flips the session from working→idle (Esc-interrupt detection). Codex rollout parsing: `response_item`/`message`/`role:assistant` `output_text` blocks = messages; `event_msg`/`turn_aborted` = interruption; `function_call` (name `exec_command` → mapped to "Bash", args JSON `cmd`/`justification`, `sandbox_permissions == "require_escalated"` ⇒ synthesize a PermissionRequest event) and `function_call_output` (regex `Process exited with code (\d+)` for success) = synthesized Pre/PostToolUse events, deduped by call_id with SHA256-prefix stable IDs.

**Liveness without SessionEnd**: Codex CLI sessions are polled every 2s with `kill(pid, 0)` (dead after 2 consecutive misses ⇒ synthetic SessionEnd). Codex thread metadata every 5s via one `/usr/bin/sqlite3 -batch -noheader -separator $'\x1f'` spawn against the newest `~/.codex/state_<N>.sqlite`: `SELECT id, rollout_path, hex(title), archived FROM threads WHERE rollout_path IN (...) OR id IN (...)` (thread UUID recovered from the rollout filename's last 5 dash-components). Compaction/context signal from newest `~/.codex/logs_<N>.sqlite`: latest `logs` row per thread where `target='codex_core::session::turn' AND feedback_log_body LIKE '%post sampling token usage%'`, parsing `total_usage_tokens`, `auto_compact_limit`, `token_limit_reached` → drives the "compacting" sprite state for Codex (Claude gets it free from the PreCompact hook).

# Usage & cost data

**Claude quota**: reads Claude Code's own OAuth token from the macOS keychain generic-password item service **"Claude Code-credentials"** — primarily via `/usr/bin/security find-generic-password -s "Claude Code-credentials" -w` (avoids the ACL dialog), falling back to Security.framework (which triggers the one-time "Always Allow" prompt). Calls `GET https://api.anthropic.com/api/oauth/usage` with `Authorization: Bearer <token>`, `anthropic-beta: oauth-2025-04-20`. Response: `five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet`, `extra_usage {is_enabled, monthly_limit, used_credits, utilization}`, and `limits[] {kind:"weekly_scoped", percent, resets_at, scope.model.display_name}` (model-aware weekly bucket). Polls with backoff; refresh is *event-triggered* on SessionStart/UserPromptSubmit (skipping local slash commands).

**Codex quota**: token from `~/.codex/auth.json` (`tokens.access_token` JWT — expiry read from the JWT `exp` claim — and `tokens.account_id`). Calls `GET https://chatgpt.com/backend-api/wham/usage` with Bearer + `ChatGPT-Account-Id` headers. Response: `rate_limit.primary_window/secondary_window {used_percent, reset_at | reset_after_seconds}`, `code_review_rate_limit`, `credits.balance` (credit ≈ $0.04).

**Cost history**: incremental scanner over `~/.claude/projects/**/*.jsonl` (and `~/.codex/sessions` + `~/.codex/archived_sessions`) with a per-file {size, mtime, offset} cache; parses assistant `message.usage` (`input_tokens, output_tokens, cache_creation_input_tokens, cache_read_input_tokens`) + `message.model`, dedupes on `message.id|requestId`, prices via live `https://models.dev/api.json` with bundled fallback JSON, buckets per day×model over a 30-day window.

# Interactions

1. **Click notch → expand panel** (nonactivating NSPanel, `.borderless`, level `.mainMenu + 3`, `canJoinAllSpaces + fullScreenAuxiliary + stationary`, transparent, custom hit-test view so only notch/panel rects intercept clicks; hover slightly inflates the collapsed shape with haptic feedback).
2. **Click a sprite or a session row → jump to that session's terminal**: walks the stored claude/codex PID's ancestry via `proc_pidinfo(PROC_PIDT_SHORTBSDINFO)` (≤12 hops) until it hits a known terminal bundle id (Terminal, iTerm2, Warp, Alacritty, kitty, WezTerm, Hyper, Ghostty, Rio, Tabby, Wave, Contour, VS Code, Cursor `com.todesktop.230313mzl4w4u92`, Windsurf, Zed, IntelliJ, PyCharm) and calls `NSRunningApplication.activate()`. Codex **desktop** sessions instead open the deep link `codex://threads/<threadId>`.
3. **Remote permission approval / question answering (the killer mechanic)**: for Claude `PermissionRequest` events, the hook script keeps the socket open (`shutdown(SHUT_WR)` then blocking `recv` with a **290s timeout**; app side waits up to 300s via an NSCondition broker keyed by `provider:sessionId:hookEventName:toolUseId`). The panel shows the tool + args with buttons "Yes" / "Yes, and don't ask again" / "No" (and number-key 1..9 shortcuts, Esc collapses). The app writes hook-decision JSON back over the socket, the script prints it to stdout, and Claude Code consumes it as the hook's output: allow ⇒ `{"hookSpecificOutput":{"hookEventName":...,"decision":{"behavior":"allow","updatedInput":{...}}}}`; "don't ask again" adds `"updatedPermissions":[<first allow suggestion from permission_suggestions, preferring destination localSettings>]`; deny ⇒ `{"behavior":"deny","message":"User denied this action.","interrupt":false}`. `AskUserQuestion` tool calls (via PreToolUse or PermissionRequest) render the question + options + a free-text "Type something" field; the answer is injected by returning `permissionDecision: allow` with `updatedInput.answers[question] = answer`.
4. **Notifications**: notification sound on Stop / waiting_for_input / PermissionRequest (per-session cooldown), **auto-muted when a terminal is frontmost** (frontmost bundle-id check against the same terminal list); importable custom sounds; haptics on hover/selection.
5. **Global shortcut** (default ⌘⌥N-style, recorder UI) toggles the panel; Esc collapses; per-provider hook enable/disable toggles in settings.
6. **Emotion analysis (optional)**: user's own Anthropic or OpenAI API key (stored in Notchi's keychain items) sends each prompt for sentiment → emotion+intensity with decay timer, changing sprite mood.

# Ecosystem (competing/adjacent tools, for comparison)

- **vibe-notch / claude-island** (farouqaldori, Notchi's acknowledged design inspiration): same pattern — hooks in `~/.claude/hooks` + Unix socket, approve/deny in notch, conversation history with markdown, Swift, macOS 15.6+.
- **Claude Pulse** (claudepulse.app, free): notch session manager, auto-discovers sessions "no config", approve tool calls with batch-approve-safe-tools policy, live 5h/weekly limits read via the Claude CLI's keychain credentials (same trick as Notchi), per-session context fill shown "breathing" in the notch.
- **Notchy** (notchy.ai / adamlyttleapps + community fork bones7456): different approach — embeds actual terminal sessions in a floating panel under the notch, auto-detects open Xcode projects.
- **NotchCode** (notchcode.dev, $19.99): Claude Code + Gemini CLI + Codex monitoring, tool approval, chat history.
- **AgentPeek** (agentpeek.app): notch+menu-bar presence for many agents (Claude, Codex, Cursor, Copilot, etc.).
- **Vibe Island** (vibeisland.app): notch control panel — see every session, approve permissions, answer questions, jump to the right terminal.
- **ccusage** (npx ccusage): pure JSONL parsing of `~/.claude/projects` for daily/weekly/monthly/session token+cost reports; the de-facto standard for offline cost math (same dedup/pricing approach Notchi reimplements natively).
- **CCSeva**: Electron menu-bar app polling ccusage-style data every 30s, plan auto-detection (Pro/Max5/Max20), color-coded % in menu bar.

Windows ports exist (notchi-for-windows, pixel-companion). Notchi's design credits also name Readout (readout.org) for the website.
